# 经过比较的四码补充与独立端点

本生成器把“全码可用”和“取形解释可用”分开。原 canonical、原来源锁、原 8,806 个训练选项均保留；新增层只处理原正式训练字集之外的字符。

1. 从固定 libre-flypy CC0 发布物选择原本存在的四码，以固定现代 Unihan 读音和产品 `explainSound` 匹配前两位；源中数字占位码被排除，不进行修复。
2. 从 `data/curated-shape-supplement.json` 的原创笔画范围选择、固定笔画事实和位置根映射独立生成策划字的编码。当前为平；中间笔画明确未展开，不冒充完整拆分。
3. 上述候选全部生成之后才读取固定外部参照。逐读音／全码对一致的发布码可保留；策划条目还要核对两端。参照只作后验比较，不提供生成代码或根定义。

实际首轮输出为 **158 个发布码字／171 个带调选项，加平 1 字／1 选项**。其中前者没有声称可解释的首末根，运行时 `shape: null`；后者保留明确端点与笔画范围。资料通知见 `data/NOTICE-four-code-coverage.md`。

## 重建与离线核对

```bash
npm run generate:four-code -- --reference /external/fixed-ixdata.json
npm run check:four-code
```

重建要求快照 SHA256 `252025614bca2f44f1c8fbcad3a4ed80bef45d224ede40102781a438a20eca17`，原件必须位于项目外。新快照不会被自动接纳，也不改旧来源锁。所有原资料都按内置固定摘要核对；新策划输入、生成器及实际音码程序依赖另记在 `data/four-code-coverage.lock.json`。

正常构建的 `--check` 无需官方原件或网络，验证固定输入、当前程序／策划资料与派生物的摘要和字节。它验证已分发结果的完整性，不假称没有原参照也重新执行了外部比较。任何变化需明确重建并复查，不提供自动重锁或猜码选项。

产物和新锁随源码包分发；官方原件不打包。编码来自 CC0 发布物，现代读音、键位、AGPL 根映射、WTFPL 笔画与原创选择各自保留来源及许可；不能把全部补充资料统一称作 CC0。
