### 任务 A：有证据的逐字教学解释（本轮实现）

建议文件：`src/data/shape-teaching.ts`、`src/domain/shape-teaching.ts`、`src/components/ShapeExplanation.tsx`；在 `CharacterInspector.tsx` 接入，并由现有码位解释入口到达。实际命名可调整，范围不要扩展成新路由或教学中心。

数据至少表达：

```ts
interface ShapeTeachingRecord {
  char: string
  verifiedCodes: readonly string[]
  coverage: 'reviewed-example'
  parts: readonly { id: string; label: string; kind: 'root' | 'stroke' }[]
  firstPartId: string
  lastPartId: string
  steps: readonly { ruleId: string; text: string; partIds: readonly string[] }[]
  evidence: readonly { sourceId?: string; url?: string; locator?: string }[]
}
```

规则说明使用原创短句与来源链接，区分“通用原则”与“已经核验适用于本字的步骤”。只有样本有逐字步骤；其他字仍显示已核验端点与来源轨迹，明确完整教学分析待补，不把通用规则自动全部挂到每个字上。

本轮建议 13 字：**某、语、框、国、试、中、鹤、木、玉、主、元、建、健**。本地核查这些字均有正式核验全码和端点；“筵”当前没有正式记录，不能因官方规则用过这个例子就添加练习答案。

| 样本组 | 用来解释什么 | 独立检查点 |
| --- | --- | --- |
| 某、语、框 | 顺序拆分与首末选择 | 中间部件存在时不等于第三码；如“语”完整教学部件与两个取码端点分别显示。 |
| 国、试 | 末形不简单等于最后一笔 | 说明先前已归属部件后如何取剩余末根；不根据 IDS 顺序假称真实书写顺序。 |
| 中、鹤 | 相交条件改变可取部件 | 应说明被排除的候选与理由，而非只显示两个最终根。 |
| 木 | 插隔及单笔归类 | 保留“捺”的语义标签，`ㄟ` 只是本库归类字形；不能让初学者以为它是注音输入。 |
| 玉、主、元 | 衍生小字及需要拆开的情况 | 逐字说明是哪一项规则；“玉”的说明不能泛化为所有含王字符。 |
| 建、健 | 廴作为部首与嵌入结构的区别 | 两字分别核验当前正式端点；不能把含廴 / 辶的字全部强制先取它。 |

上述表是待实现与逐字复核的工程任务，不是授权照抄官方整段教程。编辑人员必须对照正式字库的实际编码、端点、已有许可拆分及官方规则事实，才将卡片标为 `reviewed-example`。完整部件列表、被排除候选和规则解释由人可读数据明示，不从四码反推。

UI 验收：当前字点击首 / 末码位可到同页解释；展示部件顺序、首末高亮、为什么采用该根、根对应键位、可展开来源。没有额外路由、强制 onboarding 或默认全部泄题。查看本字答案继续走现有 assisted 逻辑；不能因卡片换组件而绕过掌握计分。键盘、读音、原文位置与已接受前缀保持。

### 任务 B：字根映射与缺字审查状态（本轮实现最小可信版）

当前缺字有 14 个单字形端点推导问题、10 个命名部件问题。Chai 候选中还有一些仅双形码碰巧一致而根标签不同，不能计入通过。任何补库记录须同时满足：

### 任务 C：无损运行资料与实际性能（本轮实现）

现状是 `library.ts` 同步导入三个大 canonical JSON，App、课程和键盘共同同步依赖它。贸然让长尾读音懒加载，会将原本仅读音的字短暂当未知字，改变文本计数和多音选择；也会制造逐字查询请求。本轮选择**同步可逆紧凑表示**，不改变 lookup 接口。

已在项目外探针验证的候选如下，所有 characters 对象解码后与 canonical 深度相等：

| 资料 | canonical UTF-8 字节 | 紧凑候选 UTF-8 字节 | canonical gzip9 | 紧凑 gzip9 |
| --- | ---: | ---: | ---: | ---: |
| readings | 3,218,047 | 859,901 | 341,627 | 222,730 |
| shape-traces | 989,572 | 514,758 | 169,724 | 151,883 |
| shape-expansion | 523,376 | 379,054 | 64,306 | 59,504 |

这是 JSON 资料表示的探针，不是最终 Vite 包体积或浏览器速度承诺。当前物理文件各多一个 LF；测量统一无空白 JSON UTF-8、Python gzip level9 / mtime0。全局字符串池方案能继续降低某些 raw 大小，却可能使 gzip 更差；工程师应分别实测两种指标。

读音方案：1,494 个唯一带调拼音表；每字 row 为 `[char, pinyinIds[], sourceMasks[], optionalFrequency]`。`kMandarin=1`、`kTGHZ2013=2`；没有 frequency 与数值 0 必须能区分，来源顺序和读音顺序保留。上述探针已重建全部 `readings`、`readingSources`、`frequency` 并深度相等，不是删掉 provenance 得到的缩小。

形码方案：固定 fields 的 row 保存字符、codes、firstRoot、lastRoot、firstRootPath、lastRootPath、idsTree，扩展行另保留 sourceIds、notes；可进一步池化，但不删除证明、来源或原树。

建议工程文件：

- `scripts/pack-runtime-data.mjs`：确定性生成、`--check` 验证；只读 canonical 和既有锁，不修改上游输入或旧生成物。
- `src/data/generated/runtime-*.json` 或一个派生包：带 schemaVersion、生成器版本及 canonical 摘要；原 artifact 和原来源锁继续提供审计。
- `src/data/runtime-codec.ts`：纯类型解码，校验 row 长度、ID 边界、mask、缺字段、重复字符与非法码点；版本不支持则失败，不默默丢行或降为未知。
- 派生运行资料单独锁：canonical hashes、生成器 hash、derived hash / counts；不能将格式优化描述为新字形来源或重写旧 provenance。
- `library.ts` 改读解码结果；domain / App / 文本 lookup 仍同步。正常构建应先 `--check`，过期产物给明确重建命令，不自动接受修改的 canonical。

验收保持全部 44,348 字 lookup 状态、读音顺序 / 来源、频率、8,806 选项、旧代码与来源、路径 / 注记、HY 计数、课程排序和键位含义完全一致。素材未变时不得以压缩为由更新旧锁摘要。

性能测量至少包含同机生产构建的前后：JS / JSON raw 与 gzip9 总量、冷启动到首个可输入字的时间、核心资料初始化耗时、输入事件到下一次绘制的分布。固定 viewport、缓存状态、CPU / 网络条件、重复运行次数，报告中注明环境；本机指标不能冒充真实低端手机表现。[INP 文档](https://web.dev/articles/inp)强调的是用户交互至可见绘制的响应，单个 SSR module 计时不能替代它。无必要不引入 Worker；先证明 parse / decode / index 的瓶颈。目标是在无语义退化的前提下显著降低初始资料体积，反馈时延不劣化；未达到就回退 decoder 接线，不牺牲数据完整性。

本轮不引入运行时异步资料或可选 proof lazy，因此无需制造加载 race。将来采用懒载时必须有明确 loading / retry / error 状态，失败不得被当未知字，也不得丢失已接受前缀、文章和读音选择；该方案须另开语义验收。

### 任务 D：跨引擎与可恢复状态验证（本轮实现）
