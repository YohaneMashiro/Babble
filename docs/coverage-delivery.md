# 覆盖扩展的本轮交付

日期：2026-10-29（Asia/Dubai）。本轮把已完成研究中的四码补充、已比较一致的 OK 拼字和本机明文库做成可运行链路。用户要求的“尽可能覆盖全部 Unicode 汉字、达到官方覆盖率”仍是主线；本报告不代表用户已经接受覆盖结果。

## 已实现的输入链路

原普通四码、15 门课程、三种主模式和原学习记录保持。新补充层新增158个发布码字和有独立笔画／规则依据的平，共159字、172个带调选项。正式四码合计8,302字、8,978个选项。发布码的根解释待补时直接说明，不从字母推根；旧教学池和根键关联不混入这类条目。

无可靠四码的字可使用已比较一致的部件拼字：OK引导，加两／三个部件双拼，共六／八码。Inspector和自定义文本都能进入，保留逐键反馈、正确前缀、提示、回退和虚拟键盘。部件助记音、公开归类和Unicode读音分别注明；本字没有普通话读音时不造音。拼字和用户编码采用独立目标及数据库，不把其成绩混入四码掌握记录。

固定许可源独立生成89,189字、112,553个候选字码对；生成完成后才打开项目外参照逐对比较。59,926字／59,930个码对一致，其他52,623个码对只读查询，不能因为同字另一码通过就进入默认评分。103个分片和部件清单只在查询／文本准备时加载，核对长度和SHA256；失败可重试，资料未就绪时不能直接跳过该字。四码输入不逐键联网。

本地字库支持严格UTF-8 TXT／TSV、受控Rime单字表和INI挂接行，硬上限16MiB／200,000行。只接纳单字四码或OK六／八码，按类别统计重复和跳过行；不执行配置。文件默认仅本次使用，可明确选择保存到当前浏览器并清除。冲突保留内置已核验记录，用户编码单独标明来源。用户文章仍只在页面内存，不随库导入保存，也不上传。

辅助记录使用串行原子事务，先恢复基线再累计；无效旧记录、打开／事务失败和超时会降级到内存，不自动覆盖旧记录。清除用户库时旧目标立即停止练习；拼字加载失败保留文章、位置和有效选择，支持重试。

## 稀有字的显示链路

实测发现𠁳可输入但宿主字体缺字，已将字形补充纳入本轮收尾。固定来源为作者明确CC0的[Jigmo 2025-09-12](https://kamichikoichi.github.io/jigmo/)，源ZIP和TTF留在项目外；派生WOFF2、准确cmap范围、来源通知及生成器随源码分发。按1024码点分片，只加载当前显示范围所需的补充字形，长度和SHA256通过后才加入浏览器字体集；加载／失败／重试状态与编码状态分开，失败保留当前输入。

派生字体共105个唯一分片，实际cmap为103,382码点，合计24,926,092B；这是全部字体分片总量，不是首屏流量。普通四码首屏保留原字体路径，不下载整套字形。该固定源包含Unicode17统一汉字；Unicode18唯一新增码点U+2B81E不在此源中，页面须明确说明当前字形未提供并保留原码点。未提供IVS的专门字形选择，不把日文字形视作中国大陆取根证明。字体补充没有增加任何本字读音或可用编码。

## 覆盖的真实集合

不同字不能与读音选项、码对相加。以下不含各用户的本机库，也不含未确认候选。

| 范围 | 仅四码 | 四码或已确认拼字 |
| --- | ---: | ---: |
| 不同字 | 8,302 | 60,891 |
| HY汉字出现次数 | 1,815／1,840 | 1,820／1,840（98.91%） |
| 通用规范汉字 | 8,049／8,105 | 8,077／8,105 |
| GB2312 | 6,625／6,763 | 6,704／6,763 |
| Big5 | 5,235／13,064 | 12,135／13,064 |
| Unicode18统一汉字 | 8,302／101,997 | 60,891／101,997（59.70%） |

Unicode17同一属性分母101,996，当前并集同为60,891字。89,189个候选字中89,188属于此统一汉字目标，另1字在外；不能把候选当作已确认可练覆盖。

固定官方查形四码参照8,409字，与官方来源社区OK镜像87,947字的真实并集为87,950字，当前可练并集仍缺27,059字。该镜像自称来自清风版，比较一致不构成官方认证或对其来源的独立证明。它不是“官方全部Unicode字数”的定义。

HY仍缺升、无、断、见、生、继、夜，共7字／20次，逐字规则复核见[常用缺字队列](common-character-gap-review.md)。还需处理剩余规范字、读音政策差异、命名部件、缺源拆分、参照不一致码和Unicode长尾。完整教学、字体显示和真实设备效果另行核验；字体不会提供读音或输入码。兼容字只有被`Unified_Ideograph`明确包含的部分进入该分母，其他兼容字、IVS、PUA和未编码字形单列。

## 复现和来源

```bash
npm test
npm run lint
npm run build
npm run audit:input-coverage
npm run audit:input-coverage -- --text /path/to/article.txt
npm run audit:input-coverage -- --help
```

新审计直接使用实际运行库、全部生产分片和固定Unicode属性范围，按集合求并集／交集；只输出统计与缺字，不输出原文。可提供两个项目外固定参照重算已知官方能力差集，也可提供固定PropList原件重新核对范围提取。旧`audit:coverage`继续只审计普通四码。

新增输入／程序／策略／产物分别由新锁记录。修改后的`dictionary.ts`、`encoding.ts`在新锁中明确更新；重新生成的105份数据产物逐字节相同。两个基础研究策略重跑后也与原型候选JSON逐字节相同。12份原canonical／runtime／旧来源锁、8,806个旧条目完整JSON指纹、8,143项旧练习和教学顺序及26键学习定义均经独立复核相同。

独立字形审计核对了105份分片的全部cmap／范围／来源／非空轮廓，抽取1,797份展开轮廓与原字体完全相同；Unicode17目标101,996字均存在于派生字体，U+2B81E明确不在其中。修复过的跨源080分片现为唯一1024字块，其他104分片保持摘要相同。字体来源、离线生成和复用约束见[说明](../tools/glyph-font/README.md)。

各层条款见[四码通知](../data/NOTICE-four-code-coverage.md)、[拼字通知](../data/NOTICE-component-spelling.md)、[Unicode目标通知](../data/NOTICE-Unicode-targets.txt)与[字形通知](../data/NOTICE-glyph-font.md)。GPLv3部件输入及底层CC BY／MIT署名随源码保留；原创生成器／加载器MIT与数据条款分开。官方原始参照、详细比较、私人用户库和上传文章不进入源码包。

## 验证状态

当前全量181项测试、TypeScript严格／未使用代码检查和生产构建通过。包括6项四码、7项生产拼字、11项用户库、9项辅助输入／存储回归及5项字形加载器回归。新增浏览器链路涵盖真实六／八码、无本字读音、候选只读、真实网络失败重试、扩展J用户编码、移除用户目标及存储损坏保护。

最终三引擎各6套、126项行为检查和70次axe扫描，合计378项／210次，实际通过且无违规。最终采纳结果逐套映射到同一生产构建；Firefox初次自由学习脚本未等待存储就绪／页面焦点的失败原件保留，修正测试前提后，三引擎自由学习均单独复测通过，未豁免原按键或无障碍断言。完整证据与判定见独立[浏览器检查](coverage-engineering-qa.md)及[实现复查](coverage-implementation-check.md)。

性能对照将旧、新生产文件均复制到WSL ext4，使用同类静态服务、完全未改探针和五组交错新浏览器／context。导航至首个确认输入的中位数378.8→397.5ms，增加18.7ms；加载后keydown到第二次RAF中位31.7→31.6ms，p95均32.4ms，共1,000个真实按键样本、零错误／加载后请求。这是本机诊断代理，含自动化和两帧等待，不是现场INP、精确模块CPU或手机结果，不能据此宣称启动提速。

冻结生产入口为`index-C31KOCG5.js`，2,094,754B，SHA256 `3455bd16b21c1ae62dc9d5e9b4a4cc4397973182765f6c4097942a5f6cdfa65d`。入口gzip9（Node22.23.4）为583,244B；扩库前基线为547,532B。新增拼字分片和字体二进制不进入首屏同步数据；整体体积及本机冷启动仍须按实测评估，不能由分片存在推定启动更快。浏览器WebKit不等于真实iOS，axe不等于完整无障碍认证；尚无本轮真人学习效果结果。
