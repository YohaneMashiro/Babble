# 下一轮补库调研：已验证路径与可执行范围

收尾日期：2026-10-31（Asia/Dubai）；主要实验完成于2026-10-30。本轮只增加研究文档、程序快照和有独立许可的研究图；正式字库仍为8,302字四码、59,926字已确认拼字，真实并集60,891字。

## 结论

已有一条来源可追溯、可复跑的补齐路径：**扩充有身份的部件选读 → 使用新版许可拆分源 → 保留结构标签 → 展开一层有来源的命名部件 → 独立逐码比较 → 常用字有限端点策划**。

```mermaid
flowchart LR
  A[固定许可拆分与部件选读] --> B[生成候选与父子来源见证]
  B --> C[完整摘要冻结后比较]
  C --> D[码对一致且来源资格通过]
  D --> E[发布增量分片并保留旧记录]
  C --> F[未一致或参照外：继续研究]
```

推荐工程范围的研究并集为 **71,551字，较生产净增10,660字**；HY可覆盖1,840／1,840次，通规可覆盖8,090／8,105字。这里的“可覆盖”是按固定参照通过、来源条件和有限端点审核得到的工程输入，**尚未接入页面**，也不代表任意读音或完整教学都已补齐。

主要瓶颈在拆分边界、部件身份和选读政策。旧许可来源的原始字键已经覆盖Unicode18目标中的101,965字；新版Yi与CHISE各自包含全部101,997字键。单纯增加大表的行数，不能直接增加可信输入码。

## 实验取得的真实增量

以下按集合求并集，不把各实验增量相加；比较范围固定，候选先完整生成，再打开参照。

| 政策 | 四码／已确认拼字并集 | 相对生产净增 |
| --- | ---: | ---: |
| 当前生产 | 60,891 | 0 |
| 原拆分，部件读音改为来源并集 | 61,558 | 667 |
| 新拆分、标签解析与读音联合研究 | 64,059 | 3,168 |
| 再加Unicode等价字形助记迁移 | 64,096 | 3,205 |
| 加有限常用字端点的全部来源研究集 | 64,102 | 3,211 |
| 上一行统一排除CJKVI来源见证 | 63,500 | 2,609 |
| **推荐：排除CJKVI，展开一层命名部件，再加有限端点** | **71,551** | **10,660** |

CJKVI部分文件的GPLv2及历史例外范围，不能直接推定与当前混合派生层的分发条件一致。推荐路径统一排除它在父、子拆分和等价见证中的直接使用，而不是按比较结果挑选某些字。396字差异保留研究身份，等待条款澄清或其他合适来源。

## 最有价值的新机制：命名部件展开

此前程序只切开一条IDS表达式已经写出的树。若一个叶节点是“某个完整汉字”，不会查该字自己的独立拆分。因此大量来源只提供两部分，而参照需要三部分；这是结构缺口，不是缺少该字码点。

本轮统一允许：对于每个有来源的两部件拆分，只选其中一个**有稳定身份**的部件，用它自己有来源的两部件拆分替换，形成三个部件。保留父字、子部件、双方来源行、结构和地区标签；只展开一次，不无限扁平化，也不由期望字母决定拆法。

推荐来源集独立生成473,352个不同展开结构，342,859个具有完整部件音码；展开层自身产生1,111,302个字码对。与已有层合并后共1,383,071个研究候选对，但只有 **70,785字／70,837个拼字对**通过固定参照。加原四码和六个实际缺字端点后为71,551字。大量未匹配候选继续留在研究层，不能全部变成默认正确答案。

每个外层拆分最多观察到24个新结构，每个结构最多84个音码组合，低于既定上限；最终版本没有因组合上限丢弃。原试验曾把`□`等占位符当成统一命名身份，已拒绝并保留失败原件。最终政策以固定Unicode属性和明确笔画身份统一过滤占位符、替代字符及PUA，不把不同未知字形互相替换。

独立checker从原始来源重新解析了全部父子见证、结构和完整码对集合；完整来源与排除CJKVI两个最终版本均通过。不是只抽查命中字或核对生成摘要。

## 常用字链路与剩余规范字

[有限常用字研究](coverage-next-common-characters.md)取得了新的有序几何来源，8字／11个音码候选中10个码对一致。无仍保留语境复核，见的xiàn不通过；其余7字有8个可审端点码对，其中大已经有拼字覆盖，实际补升、断、见、生、继、夜六字。无则由新的部件读音政策获得拼字，因此HY研究集合可全覆盖。

推荐路径仍缺的15个规范字是：**䐃、丞、侴、函、单、卺、堕、墼、央、尢、廿、烝、臧、艮、𠙶**。

- 其中11字在当前现代读音声码下仍有可核对的四码前缀；下一批应按有限端点范式逐字补独立根／几何证据，不从末两字母倒推根。
- 䐃、侴、堕、尢在固定参照中没有与当前现代读音声码匹配的四码。应分别审查读音来源、参照版本和有来源的拼字，不能强改现代默认音。

主代理另做了整字字典异读的补充实验：固定CC0发布码与六属性产生40,404个不同读音码候选，双实现集合相等；后验确认29字／31个码对，但相对最终研究集只多囝、堕、夗、尢四字。这些**不纳入主推荐指标**。例如堕的命中是旧词典huī，现有现代音为duò；用它填“现代常用字覆盖”会误导学习。整字异读与可供拼字的部件助记不能共用默认准入政策。

## 距离目标还差什么

推荐路径对固定已知官方四码＋OK并集87,950字，仍缺 **16,399字**：

| 剩余类别 | 字数 | 下一步工作 |
| --- | ---: | --- |
| 有源键，没有允许的两／三件切分 | 2,080 | 审查原子部件、语法和有证据的结构组合；不能只截断四部件 |
| 有结构，缺完整部件选读 | 2,490 | 按共享部件找独立名字、助记或字典依据；不造整字读音 |
| 有候选，但没有参照一致码 | 11,829 | 分开检查部件边界、身份变体、音码及参照版本 |

全Unicode18主目标还缺30,446字；官方参照本身也没有为全部该目标提供可核对答案。参考外的独立候选必须另审来源与规则，不能仅因程序能生成就声称达到官方覆盖。兼容字、IVS、PUA和未编码字形仍分别处理。

后验差异排行榜中的疒→BK、囗→KL、廾→CC等只是调查线索。公开普通形码键位的记忆用语不直接证明完整OK读音；即使容易联想到病／框／草，也要有独立的部件身份和助记依据后再统一实验，不能把期待码直接写成规则。
