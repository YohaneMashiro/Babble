# 官方快照校对与 Chai 试验

更新日期：2026-10-27（Asia/Dubai）。这是构建期数据工具，不改变学习界面的按键处理、课程或浏览器存储。

## 两条数据链

```text
官方 ixdata.json → 外部缓存 → 版本差异 + 现有库覆盖报告
明确来源的字形 + 根定义 + Chai 配置 → 独立拆分候选 → 与参考比较
                                                     ↓
                                           规则、来源及逐字复核
                                                     ↓
                                           后续审查生成物与锁
```

官方查形记录用于发现缺口及比较。Chai 的拆分输入、配置及生成结果单独记录；参照中的编码、根名或拆分不能直接补进候选。只有编码一致仍不足以成为教学记录，还要有可复现的字根、笔画或部件路径及明确的数据来源。

## 日常校对

在项目根目录、Node.js 22.12+ 环境中运行：

```bash
# 一次公开请求；后续使用 ETag / Last-Modified 条件请求
npm run audit:official

# 使用本机已有缓存，完全离线
npm run audit:official -- --offline

# 不访问网络，检查自行准备的项目外参照，详细报告也留在项目外
npm run audit:official -- \
  --reference /absolute/outside/project/ixdata.json \
  --report /absolute/outside/project/official-review.json

# 重算实际运行库对默认文章的覆盖
npm run audit:coverage
```

工具默认把官方快照放在项目外的用户缓存目录。终端只打印摘要；包含官方逐字字段的报告须通过 `--report` 写到项目外。更新失败保留上一份已验证快照，不将失败响应、HTML 或未验证 JSON 当作新版本。完整参数及缓存布局见[官方校对工具](../tools/official-ix/README.md)。

报告把新增 / 删除的字与编码、字根、拆分、读音、标记变化分开。比较训练库时按已核验双拼表匹配现代来源读音，不把官方编码数组与拼音数组按下标配对；命名部件、参考结构异常和读音来源差异需分别处理。

发现变化后先查看差异与来源，再决定是否调整本项目生成规则或输入。该命令不更新 `src/data/generated/` 或任何来源锁；参考快照换版也不会让现有生成器自动接受新摘要。

## Chai 试验的验收边界

试验入口为 `npm run audit:chai -- --help`，完整配置、外部核心库准备和运行方法见 [Chai 试验工具](../tools/chai-pilot/README.md)。上游代码、远程字形库、详细拆分报告均使用项目外路径，Babble 的正常安装和构建不引入 Chai 的前端依赖。

首批目标来自《花园中》当前缺失的 24 个不同汉字，共 82 次出现。运行结果需保留实际核心版本、字形输入摘要及试验配置，区分“能分析”“根一致”“编码一致”与“允许接入训练库”。

将试验结果纳入正式数据前，应逐项完成：

1. 确定所采用字形数据的来源与使用条款。程序的 GPL 声明不能自动代替远程字形数据的许可。
2. 为命名部件建立有来源的形状、笔画及根键对应，不能只把官方名称替换成近似 Unicode 字符。
3. 逐字验证小字衍生、相交不拆、插隔、取大、廴辶等实际涉及的规则；禁止按官方答案反向修饰候选而省略依据。
4. 回归已有已核验字，检查新增规则有没有破坏原有结果；分别统计字、读音和全码，保留未匹配项。
5. 审查生成物、来源通知和固定版本锁，再通过测试及构建。原始官方快照和详细报告不随公开源码包分发。

本轮工具的成功运行不等于新增 24 字已通过以上验收。实际试验结果及剩余问题见下方记录。
