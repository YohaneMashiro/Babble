# 大字集扩展的工程交接

日期：2026-10-28（Asia/Dubai）。用户明确要求：尽可能覆盖 Unicode 汉字、对齐官方实际输入覆盖；研究透彻后交由工程师实现。本文件是实施任务，研究事实见 [覆盖调研](coverage-expansion-survey.md)，独立研究复核见 [复核报告](coverage-research-check.md)。本文件本身不代表产品已扩库。

## 工程目标与既有基线

默认正式库现在仍是 8,143 字／8,806 个带调读音与全码选项；HY 1,758／1,840 次可练，缺 24 字／82 次。通规 8,105 字中实际只覆盖 7,895 字，一级缺 98 字。先保留原字码、解释、排序、课程范围和学习记录，再增加能力；不能仅改统计或把研究候选改名为已核验训练数据。

目标不是给所有字硬凑四码。官方实际是常规四码＋OK 部件拼字；常规音形、编码可用但解释待补、6／8 位拼字、独立社区扩展及用户本地明文库须有不同证据和语义。Unicode 主目标固定为 18.0 的 `Unified_Ideograph` 101,997 字，兼容汉字及其他字符另记；同时保留当前 Unicode 17 基线的可重算结果。

## 1. 先拆开数据资格，接入明确的四码补充

建议新增 discriminated union 或等价模型，不再要求“有全码”必然附带两个可显示根对象：

```ts
type CodeEvidence =
  | { kind: 'published-and-compared'; sourceId: string; referenceSha256: string }
  | { kind: 'independently-derived'; sourceId: string; ruleEvidenceIds: string[] }
  | { kind: 'published-uncompared'; sourceId: string }
  | { kind: 'user-imported'; importId: string }

type ShapeEvidence =
  | { kind: 'verified-endpoints'; first: ComponentRef; last: ComponentRef }
  | { kind: 'partial'; first?: ComponentRef; last?: ComponentRef }
  | { kind: 'unreviewed' }

// 与现有 root-sequence / endpoints / unreviewed 教学范围独立。
// 每个 pinyin/code pair 自己持有证据，不能整字批量升格。
```

具体类型名由工程师决定，以下约束必须成立：

- 保留旧库为完整、稳定的原证据层；不改 canonical、旧来源锁或旧工具输入来接纳新层。新生成器、策划输入、来源通知和生成锁分别新增。
- 从已持有的 CC0 发布码表和当前 Unihan 独立选出读音匹配的四码，再用固定官方参照作后验比较；只接入通过的字码对。当前可确认新增 **158 个不同字**，来源与逐项研究结果在项目外 `local/all-missing-classification.json`。
- 解释待补时，第三／四码可显示“形码解释待补”，不得由字母倒推根或填入相似字符。形码专项课、字根表及教学课仅使用有对应证据的条目。
- 普通四码练习／文本练习可使用编码通过的记录；其协助和独立计分仍按实际输入目标。查询页区分编码出处、端点证据和完整教学范围。
- 41,261 个发布码＋现代读音候选不是全部已核验；与当前参照无匹配或未比较的码对默认不混入已核验课程。保留可查询候选身份及差异审查，不删除长尾来源。

第一阶段验收：旧 8,143 字逐字、逐码、来源和课程顺序无变化；新增集合按字码对独立计数；若 158 字全部接入则合计不同字应为 8,301，HY 为 1,813／1,840，通规 8,048／8,105。这些是检查值，生成器实际输出若有差别必须解释，不能调整筛选凑数。

## 2. 补有证据的规则字与命名部件

平已在项目外 `local/ping-proof.{py,json}` 通过独立推导：许可 Strokes 第244行＋公开同字插入规则＋已有根键表＋现代读音，最后再与官方码根核对。可新增原创策划记录进入新层，覆盖 HY 另外 2 次；预期随阶段1达到 1,815／1,840（98.64%），仍不是覆盖完成。

继续处理无、生、大、见、升、夜、断、继。不要等待自动引擎才能处理有限常用字；使用明确笔画、部件范围与规则应用逐字策划，再交独立 checker。命名部件需要稳定 ID、名称、首末位置、笔画／几何范围与来源，允许不能单用一个 Unicode 字符表示的部件；见下不能直接改名儿，既左／即左的来源命名差异要保留。

62 个读音政策差异另建队列。固定 Unihan 的其他属性已为30字提供匹配音，其中19字已有端点轨迹；若接入，应明确显示属性、字典／地区／罕见读音的身份，不默默改写首选现代音。所有原始输入和生成器须锁定，新旧读音层可以分别查询和选择。

## 3. 将广覆盖部件拼字接入产品

输入基线为固定 radical 源及其条款，详见 [研究工具](../tools/coverage-research/README.md)。该工具已把两个基础政策独立生成和比较分开；工程版须另作生产生成器，加入公开的四部件整体规则及有明确上限的读音候选政策，保留每条的源行、部件、选读与出处。

研究已实际跑出 89,189 个源字键，其中 89,188 字属于 Unicode18统一汉字目标；后续政策有112,553个候选字码对，**59,926字至少一条与固定官方来源镜像一致**。只能逐字码对保留“已比较一致”状态。未一致的独立扩展不能作为“官方正确码”评分，参照外部分也不能假称不存在或直接丢掉。

产品接入应形成完整链路：

1. 原创生成器＋许可输入、全局规则与来源读音生成候选，完全生成后才读取参照；参照不决定拆分或选读。固定参照版本、输入摘要、policy版本、生成物摘要和集合统计。
2. 用紧凑分片储存派生资料，保留部件、读音、双拼和来源定位。不要把全部原始字形／详细比较或近九万完整对象直接塞入首页同步 JS。
3. 自定义文本分析前准备一次所需扩展索引，状态明确为加载中／可重试／可练；不能在资料未就绪时误标未知并跳过。输入过程中不逐键或逐字联网。切换、取消、失败不得丢失用户原文、选读或已接受前缀。
4. 当前字有可靠四码时优先沿用四码训练；无可用四码但有已比较拼字时提供明确的“部件拼字”训练。继续保持自由／学习路径／自定义文本三主模式，不新增一套导航中心。
5. 拼字 UI 解释的是 OK 引导和两／三个部件双拼，不能仍标“声母、韵母、首形、末形”四位。保留逐键对错、正确前缀、回退、提示及实体／虚拟键盘。显示本字无读音与部件有读音是不同事实，不能把部件音拼成假造的本字读音。
6. 查看答案算协助；学习目标必须含输入方案及完整编码，6／8位拼字不能写进原四码同一目标的掌握连胜。旧 IndexedDB 记录可继续恢复；新记录持久化失败仍内存可用。
7. Inspector 列出来源、明确部件和读音、拼字码，以及四码／拼字的证据身份。独立社区候选保留待核验身份，不在默认正式评分中冒称官方。

单独验收：没有本字普通话读音的真实增补平面样本能通过部件拼字完成；两部件6位、三部件8位均可操作；不把8位目标截为4位；码对来源可查；旧四码各模式行为无退化。覆盖必须按“可查、正式四码可练、已比较拼字可练、独立候选、教学范围”分别统计。

## 4. 用户本地明文覆盖层

实现用户本机选择文件的通用明文导入，不复制或内置未经明确再分发许可的官方原库。至少支持受控的 TXT／Rime 单字 TSV，以及官方个人挂接说明的 INI `编码=序号,词条`；不得执行 YAML、Python、模板或插件代码，不反编译 BIN。

- 文件在浏览器读取，有字节／记录数硬上限、严格 UTF-8 解码和行格式验证，失败保留原导入状态。单字／词语、简码／全码／OK拼字分别识别，不把所有行计成不同汉字。
- 来源为“用户导入”，不得因表头声称官方就升级成自带已核验来源。有冲突时保留原已核验记录与解释，呈现用户库候选，不静默覆盖原正确答案。
- 导入库与粘贴文章是不同数据。默认本次使用；若提供保存在当前浏览器的选择，必须在同一导入界面明确表达并可清除。用户文章仍遵守原有不落盘约束，不能为库导入顺带保存文章。
- 本机库不上传，不进入源码包、产品跟踪或外部校对请求。尚未取得的官方原包不能在测试里伪造成已经审核的官方全库。

## 5. Unicode 显示与覆盖看板数据

Unicode属性清单、官方查形、官方来源OK镜像、产品四码与拼字取真实集合并集／交集，不相加条目数。兼容字、IVS序列、PUA和未编码字单列；不要用归一化悄悄消掉用户原文字符。当前统计脚本和目标摘要位于项目外 `local/unicode-target-audit.{py,json}` 与 `benchmarks/`。

有字码却无字体的字要能识别这是显示问题。可按需使用作者明确CC0的Jigmo字体或其他有来源的字形，按区域分片，保留地区字形边界；字体不会提供本字读音或小鹤根。不得为扩展覆盖加载约34MiB全字体到首屏。实际读屏／目标设备仍需要后续验证。

## 验证与交付顺序

每个阶段应交付可运行链路和对应实测，不只留下配置：

1. 用例覆盖生成的确定性、输入锁／规则锁、逐码对后验核对、冲突拒绝、来源保留、加载／失败状态、6／8位目标与记录隔离、本地文件边界。避免只验证自己的实现常量。
2. `npm test`、`npm run lint`、`npm run build`；旧字库等价审计及覆盖分母重算。同步字库体积与冷启动／加载后输入分别测，保留可复验的原始基线，不只保存到易失临时目录。
3. 三引擎自由／课程／文本原有smoke，加真实稀有字的四码补充、拼字、导入、刷新／内存降级／IME／320px／深色与axe回归。不以WebKit等同真iOS。
4. 新资料分发须有各自通知、源输入、生成器与摘要；原始官方镜像和本机用户库不打包。最终源码归档逐项对照，再由独立checker给本阶段结论。

阶段1通过不能改称已满足全部Unicode；阶段3的候选总数也不替代官方输入覆盖的实际并集比较。后续继续依据用户文章和目标集合缺口推进，直至用户接受覆盖结果。研究通过只允许进入工程，不代替覆盖目标完成。
