# 整篇文本自动注音与多音消歧调研

2026-11-02。结论：已有可用的上下文注音模型，Babble 可以从「每个多音位置先要求选音」改为「导入时自动预选，正常连续输入，点字修改」。本轮完成资料核验和本机小型对照，尚未修改练习行为、安装产品依赖或接入模型。

推荐把自动选读与现有字库分开：先消除同键码选项造成的打断，以浏览器词组方案建立可纠正的自动预选；真正语境模型优先以 g2pW 做质量参照，再验证可承受的本地推理版本。现成 g2pM 发布包本次诊断效果不足，不建议直接作为默认答案；2026 年的 g2pO 值得跟踪，但尚未找到可核验的作者权重与完整分发许可。

**候选与可交付程度**

| 方案 | 已核对能力与体积 | 对 Babble 的判断 |
| --- | --- | --- |
| [g2pW 作者实现](https://github.com/GitYCC/g2pW) | 上下文 BERT 多音消歧，公开 ONNX；[作者托管的 ONNX zip](https://huggingface.co/YC-Chen/g2pW/tree/main) 元数据为 589,075,404 字节 | 成熟的神经模型候选；原始发布包约 589 MB，不放进网页默认首屏。浏览器量化、拆包或本机推理需要另做适配与测试 |
| [g2pM 作者实现](https://github.com/kakaobrain/g2pM) | 轻量 BiLSTM，NumPy 推理；本次 PyPI 0.1.2.5 wheel 为 1,675,906 字节，权重文件为 1,607,180 字节 | 易做小体积端侧试验，但本次同题对照不支持直接准入为默认注音 |
| [pinyin-pro 官方文档](https://pinyin-pro.cn/use/pinyin.html) | 词典＋分词方案，原生 JS；3.29.5 核心发行文件 325,698 字节，gzip9 为 141,919 字节 | 最快接入当前纯前端架构的基线。不是神经模型，不能把「有输出」当作「语境已确定」 |
| [g2pO：Interspeech 2026 论文](https://www.isca-archive.org/interspeech_2026/chen26i_interspeech.pdf) | 论文报告 3.99M 参数，词典增强、开放读音输出；CPP 99.15%，RCPP 99.03% | 新近轻量路线；论文未给自身代码／权重下载链接，本次检索未找到可核验发布物，暂列跟踪项 |

[g2pW 论文](https://www.isca-archive.org/interspeech_2022/chen22d_interspeech.pdf)的 CPP 测试为 99.08%，[g2pM 论文](https://www.isca-archive.org/interspeech_2020/park20c_interspeech.pdf)为 97.31%。这些是指定数据、划分和训练配置上的多音目标指标，不是任意整篇文章正确率。g2pW 论文说明其公开权重来自内部 MPB；当前 v2 检查点仍需单独核验训练配置，不能套用 CPP 实验分数。[CVTE-Poly 作者复查](https://github.com/NewZsh/polyphone)另指出 CPP 错标、读音分布偏差和原测试集的非多音目标问题。

g2pO 的新论文已从 ISCA 官方站取得并阅读：Table 2 报告上述数字；其词典汇总《现代汉语词典》第七版、CC-CEDICT 和 Zdict。参数小不等于已提供可合法分发、可在浏览器运行的模型；本次没有下载或训练其权重。[G2PA](https://www.isca-archive.org/interspeech_2024/yang24_interspeech.html)需要音频与文本，不适合只有 TXT 的输入。

**当前有多少选择其实不必打断**

本机用实际 `readingOptions`、两个真实查询库和既有默认 `the_Tower_of_Babel.txt` 计算，未将原文发送给模型服务，报告只保存汇总：

| 当前规则 | 双拼级 | 仅普通四码，未计 OK 回退 |
| --- | ---: | ---: |
| 可练汉字出现位置 | 1,840 | 1,815 |
| 多个读音／编码选项的位置 | 503 | 488 |
| 所有选项已有完整输入码，且输入码完全相同 | 232 | 232 |
| 仍有不同输入码或无可用码选项 | 271 | 256 |

双拼级那 232 次约占多选位置的 46.1%。只从按键目标看，用户无需先区分这些候选；若要展示精确声调读音，仍应使用语境建议并允许纠正，不能把同键等同于同一发音。四码中另有同读音多编码的可能，语音模型只能选读音，不能证明应使用哪套取形编码。

**本地试验：不能只依据论文选型**

固定了 [73 条原创合成句、74 个去声调目标](research-assets/contextual-pinyin/synthetic-fixtures.json)，包括行／长／重、地名、姓氏、混排与容易混淆的词。全部输入是专门构造的诊断句，不是随机真实语料，不能推算总体准确率。词典扩充只是同一题集的后续实验，没有修改预期标签。

| 实际运行方案 | 基础拼音匹配 | 备注 |
| --- | ---: | --- |
| pinyin-pro 3.29.5 核心，分词算法 1／2／3 | 65／74 | 调用 Babble 真实 `explainSound` 后，同双拼键码目标也是 65 |
| ＋modern 词典，算法 1／2 | 67／74 | 算法 3 为 66；额外 JSON gzip9 为 623,366 字节 |
| ＋complete 词典，算法 1／2 | 68／74 | 算法 3 为 67；额外 JSON gzip9 为 3,804,809 字节 |
| g2pM 0.1.2.5 官方模型，NumPy 2.3.3 | 45／74 | 73 句全部调用神经预测；独立复算实际双拼键码也是 45／74 |
| 同一 g2pM 包只取词典首选的对照 | 36／74 | 上下文模型有改善，但不足以作为本项目默认 |

complete 词库仍把「还钱」「系好鞋带」「和面」及单／曾／解先生中的目标读错，影响实际双拼按键，不只是声调区别。g2pM 还出现「银行」预测正确，但「我在银行工作。」误成 xíng 的反事实结果。已经检查 Unicode 位置、输出长度、神经调用、权重与固定作者提交的字节一致性、数值有限性；没有复现原论文的完整基准或旧 NumPy／PyTorch 环境，因此结论限定于这个实际发布包和本题集。

pinyin-pro 的 20,000 码点合成文本在 Node 22 预热后中位数约 26–30 ms；这不是手机或浏览器速度，也未测试神经模型的浏览器性能。g2pW 约 589 MB ONNX 模型发布包本次未下载、未运行；没有声称其在 Babble 文章上的准确率。

汇总与版本证据见 [pilot-summary.json](research-assets/contextual-pinyin/pilot-summary.json)。原运行程序、逐目标结果、wheel 摘要和独立环境位于 `/root/.cache/babble-pinyin-survey/`；原始词库、模型、wheel 和用户文章未复制进这些调研附件。

**工程接入链路**

1. 导入文章时保留原文码点索引，按句或带左右上下文的窗口注音；在后台一次准备候选，不在每次按键时调用模型。每次出现位置单独保存建议、提供者与模型版本。
2. 使用现有 `isHanCharacter` 判定汉字；注音器只提供读音建议。pinyin-pro 对部分扩展区字给出空拼音和 `isZh:false`，不能据此删字或替换 Babble 已有读音库。
3. 将建议规范化后匹配当前字已经收录的读音／训练选项。保留字典声调，输入目标仍由 Babble 原声韵映射生成；不由模型拼音造新四码、字根或 OK 部件编码。
4. 同键码候选自动合并为一个输入目标。其余位置默认使用可匹配的自动选读，用户直接连续打字；点当前字或读音可修改，修正只作用于该位置或用户明确指定的词组。
5. 无结果、来源冲突或无合法训练选项时保留选择／跳过入口。词典匹配没有经校准的概率；g2pW 公开调用也未直接返回内部概率，不能凭固定阈值虚构「高置信正确」。普通建议不要求逐字确认。
6. 自动选读与使用答案提示分开：自动看到拼音不应等同于揭示小鹤键码；显式展示完整编码的既有协助规则继续适用。修正模型错误时避免把错误自动目标造成的误判计入用户掌握记录。
7. 原文和逐次建议默认只保留页面内存，保留既有上传限长与刷新清除语义。若未来引入服务端预测，它会改变「原文在本机处理」的产品约定，不能作为这次调研的隐式接入。

优先落地顺序是：同码免选 → 可纠正的浏览器词组预选 → 在固定样本上评估 g2pW 的实际检查点及端侧压缩。新增模型应通过大陆常用词、人名／地名、长文窗口、英文／标点／emoji／扩展汉字、逐次选读及三引擎兼容测试。g2pO 等有明确可得权重后再进入同题评估。

**运行与许可边界**

- g2pW 作者代码及作者托管权重模型卡标明 Apache-2.0；使用拼音和简体时需核对 `style='pinyin'`、`enable_non_tradional_chinese=True`。逐字简转繁不等于已符合大陆读音规范。见[作者 API](https://github.com/GitYCC/g2pW/blob/master/g2pw/api.py)和[权重模型卡](https://huggingface.co/YC-Chen/g2pW/blob/main/README.md)。
- g2pM 代码为 Apache-2.0，随包 `digest_cedict.pkl` 的词典来源另行保留；[CC-CEDICT 官方](https://cc-cedict.org/wiki/)当前说明 CC BY-SA 4.0。实际快照与通知需要固定，不能把整个来源链笼统写成 Apache。
- pinyin-pro 3.29.5 发布包附 MIT LICENSE；`@pinyin-pro/data@1.3.1` 发布 metadata 标为 ISC、包中未附 LICENSE，[当前源码](https://github.com/zh-lx/pinyin-pro/blob/main/packages/data/LICENSE)则为 MIT，modern 明示《现汉7》来源。[扩充文档](https://pinyin-pro.cn/use/addDict.html)的能力说明不替代具体分发物的来源核对，本轮未将扩充词典入库。
- [ONNX Runtime Web](https://onnxruntime.ai/docs/tutorials/web/build-web-app.html)提供浏览器推理路径；具体模型的分词器、算子、内存、加载体积和索引对齐仍需验证。WASM 端口如果只是同一词典算法，不会自动变成语境神经模型。
