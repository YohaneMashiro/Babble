# g2pW 自动注音交付

日期：2026-11-02。本阶段在 Babble 的现有两级训练与字库上接入真实 g2pW v2 ONNX 推理。

## 用户链路

首次进入网站、打开文本编辑器、粘贴文字和填入《花园中》都不下载模型。《花园中》直接使用本机预处理的逐位置读音。点击“上传 TXT”会同时启动本站模型加载并打开原生文件选择器；粘贴文本另有“启用 g2pW 自动注音”按钮。首次必要模型资源约 175.5 MB，入口显示体积提示，过程显示进度。

模型就绪后，当前文本在 Worker 中自动注音。开始练习后，有效预测直接选择已有字库中的对应读音，“读音已自动选择 · 更改”可逐处修改。同一个字不同位置独立保存选择。连续原文、键盘和空格确认下一字保持现有行为。模型加载失败可重试，也可立即手动选音练习。

修改文字、重新选文件、取消编辑都会取消过期注音，防止旧结果覆盖新内容。已加载的模型在当前页面复用，包括两级切换；刷新后不保留用户文章。所有模型资源从本站下载，原文不发送到远程注音服务，不写入学习进度存储。

## 默认文章与读音边界

《花园中》2,197 个码点逐项对齐，1,840 个汉字均获得读音，其中 837 处进入神经模型，其余使用作者字典。预置读音与重新执行本地 int8 推理完全一致。

| 模式 | 原需逐处选音 | 自动解决 | 保留手选 |
| --- | ---: | ---: | ---: |
| 双拼 | 503 | 500 | 3 |
| 音形基础四码 | 488 | 485 | 3 |

这张表按基础字库统计，不包含辅助拼字。三处保留项均为“和”：模型预测 `han4`，当前读音来源不包含该用法，因此没有强行选择其他读音。自动注音只选择已有来源选项，不制造汉字读音、取形或编码；同音但编码不同的情况仍交给用户确认。仅展示读音不扣独立练习记录，展开实际编码选项时才记录相应协助。

g2pW 并不保证每处语境都正确。本机 73 个原创诊断句的 74 个指定目标中，原始和量化模型均有 63 个符合预期；这不能作为通用准确率。《花园中》两版模型有 1 处选音不同。详细复现、来源、许可及结果见 [模型构建说明](g2pw-model-build.md)。

## 验证与复现

- `npm test`：包含逐处选音匹配、默认文章绑定、官方 Python/BERT 对照分词，以及 Worker 按需加载、取消和重试测试。
- `npm run lint`：严格类型和未使用代码检查。
- `npm run check:g2pw`：离线核对来源摘要、词表、8 个模型分片、拼接权重、运行时和文章位置。
- `scripts/g2pw-smoke.mjs`：在 Chromium、Firefox、WebKit 中执行实际模型下载和 WASM 推理，检查零首屏模型下载、逐处改音、空格训练、过期任务、级别复用与存储边界。
- 受影响的原有连续文本、自定义文本和两级入口套件继续运行真实浏览器回归。

独立工程检查发现并修复了 BERT 词表中的 U+2028/U+2029 被错误分行、导致 token ID 偏移的问题。现在浏览器预处理与固定版本官方 Python 分词样例逐项一致，真实浏览器能分别预测“银行”和“行走”。

完整部署包含模型资源。源码下载包包含小型元数据、许可、预置读音及重建脚本，省略模型和运行时二进制；按构建说明可重新生成。原始 Word、私有需求文档和下载缓存不打包。本阶段未发布站点。
